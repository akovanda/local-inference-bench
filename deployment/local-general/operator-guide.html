Check and restart

systemctl --user status local-general-backend.service local-general-gateway.service
curl --fail http://127.0.0.1:11441/healthz
curl --fail http://127.0.0.1:11441/readyz
journalctl --user -u local-general-gateway.service -n 80 --no-pager
journalctl --user -u local-general-backend.service -n 80 --no-pager

# Gateway-only restart: leaves LFM loaded.
systemctl --user restart local-general-gateway.service

# Backend restart: interrupts generation and reloads LFM.
systemctl --user restart local-general-backend.service

A successful liveness check proves the gateway process is up. A successful readiness check proves that the backend health route is responding; neither is a semantic quality check. Initial loading includes artifact verification and GPU placement.

Rotate the API key

The gateway reads its token file on startup. Rotation replaces the single accepted key; clients must update their configured secret.

python3 - <<'PY'
from pathlib import Path
import os, secrets
p = Path('/external/user/.config/local-general/api-token')
temporary = p.with_suffix('.new')
fd = os.open(temporary, os.O_WRONLY | os.O_CREAT | os.O_EXCL, 0o600)
with os.fdopen(fd, 'w') as f:
    f.write(secrets.token_urlsafe(48) + '\n')
    f.flush()
    os.fsync(f.fileno())
os.replace(temporary, p)
PY
systemctl --user restart local-general-gateway.service

GPU ownership and the benchmark

The T4 is dedicated to this service. The previous serial public benchmark was checkpointed with its identity-verified supervisor's normal SIGTERM cleanup. Two profiles are fully completed; Flash Next Coder has 40 completed cases and an interrupted request to retry. All old scores, requests, and partial-stream evidence are preserved. A separate checkpoint receipt records the reason and original resume command.

While LFM is running, its supervisor owns the GPU and temporarily pauses the original local-codex-ollama-cpu container. This prevents an old OSS request or a benchmark window from loading another model into the same GPU. Stopping the backend cleans up its own server process and restores that container. Its original image, model files, port mapping, and configuration are preserved.

To resume the benchmark, first schedule a service outage and stop both service units. Use the saved command; the benchmark resumes unfinished cases, preserving prior attempts.

systemctl --user stop local-general-gateway.service local-general-backend.service

# Verify the backend stopped and the original container was restored.
docker inspect --format '{{json .State}}' local-codex-ollama-cpu
nvidia-smi --query-compute-apps=pid,process_name,used_memory --format=csv

cd .

The backend deliberately refuses to start while the benchmark supervisor is alive. Stop the benchmark through its owned supervisor and verify clean restoration before starting LFM again. Do not remove safety guards or signal unknown GPU processes to force a start.

Configuration and measured behavior

The backend uses the same existing QAD-Q4_0 artifact and 73,728-token context as the completed LFM public benchmark, with automatic GPU placement and one model slot. Reasoning is separated into its own response field. The gateway defaults to 8,192 output tokens and permits explicit requests up to 65,536, subject to actual remaining context. The backend owns exact tokenization and context enforcement. Output and queue limits are in service.env; model placement is in lfm-backend.json.

OpenAI reasoning_effort low/medium/high is accepted as ignored compatibility metadata. Ollama think controls exposed reasoning only. LFM still reasons internally. A token cap may therefore expire before the final answer. Do not describe these flags as disabling reasoning or promise the single-request benchmark throughput to simultaneous clients.

The gateway does not store prompts or generated answers in logs. The backend runs without verbose prompt logging. The deployment smoke-test outputs are synthetic examples stored separately as explicit verification artifacts.

Model sourcing

The standing sourcing policy is saved in /external/user/.codex/AGENTS.md: prefer original developers, accept traceable reputable quantizations when useful, and push back firmly on weak provenance, misleading claims, opaque packaging, and poor evidence of usefulness. Routine credible choices should continue without extra approval gates. Experiments stay clearly labeled and separate from shared services.

This endpoint uses Liquid AI's own GGUF release at revision 0912d33141f77e10705345a6732bfd83f0252fdc, with model SHA-256 d1c03f73ecaf61017d70419eec9e5dc0b05d50ae26c23d522829b934fbabf8a5. Deployment independently checked the pinned revision's Hugging Face LFS metadata against that hash, and startup rechecks the full local file.

The model-source audit is results/local-general-service-20261024-v1/model-source-audit.json. It identifies Unsloth and bartowski quantizations, ISTA-DASLab research variants, developer-published Bonsai, and the already-deferred community Gemma StyleTune separately. The original local OSS artifact has a fixed hash; its complete upstream lineage was not independently established by this audit. A mismatch with today's mutable registry tag is not evidence of malicious alteration.

Weights in a data format can still produce deliberately manipulated behavior, and runtime parsers need ordinary software maintenance. A matching hash, malware-scan badge, or a good benchmark score cannot establish that trained weights have no hidden trigger. This service returns text and proposed tool calls; callers retain control of tool execution and authorization. No model repository's Python code is needed to load this pinned GGUF.

Network routing and rollback

Only Tailscale Serve port 8446 is added. Existing Serve handlers and Funnel configuration are snapshotted in deployment evidence and remain intact. Both application listeners bind to loopback. The route is private to the tailnet and follows its existing policy.

tailscale serve status

# Remove only this service's HTTPS route, preserving every other route.
tailscale serve --https=8446 off

# Stop startup and release the service's model/GPU.
systemctl --user disable --now local-general-gateway.service local-general-backend.service

Stopping the backend restores the original OSS container; it does not overwrite or delete the benchmark or either model. Initial deployment and test receipts, including source and dependency hashes, are in the deployment evidence directory.
