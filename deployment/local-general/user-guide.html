Local General

Connect applications to the local LFM 2.5 24B A2B model through one stable name: local-general. Use it for chat, summarization, structured extraction, and application-controlled tool use.

Connect

Your device or service needs access to this Tailscale network. Ask the service owner for an API key, and store it in your application's secret settings.

For an application running directly on UCS, the local base URL is http://127.0.0.1:11441/v1. Authentication is still required. Other devices should use the HTTPS address above; localhost would refer to their own device.

export LOCAL_GENERAL_BASE_URL='https://device.example.invalid:8446/v1'
# Set LOCAL_GENERAL_API_KEY using the key supplied by the service owner.

curl --fail-with-body "$LOCAL_GENERAL_BASE_URL/models" \
  -H "Authorization: Bearer $LOCAL_GENERAL_API_KEY"

curl --fail-with-body "$LOCAL_GENERAL_BASE_URL/chat/completions" \
  -H "Authorization: Bearer $LOCAL_GENERAL_API_KEY" \
  -H 'Content-Type: application/json' \
  --data '{
    "model": "local-general",
    "messages": [{"role": "user", "content": "Summarize why request timeouts are useful in one sentence."}],
    "max_tokens": 2048,
    "temperature": 0,
    "stream": false
  }'

Read the answer from choices[0].message.content. Requests and conversation history stay on this model service; the caller controls any external tools or retrieval it adds.

Python and JavaScript

Use an OpenAI-compatible Chat Completions client. The SDK's API key is this service's key.

Python

# pip install openai
import os
from openai import OpenAI

client = OpenAI(
    base_url=os.environ["LOCAL_GENERAL_BASE_URL"],
    api_key=os.environ["LOCAL_GENERAL_API_KEY"],
    timeout=900.0,
    max_retries=0,
)

response = client.chat.completions.create(
    model="local-general",
    messages=[
        {"role": "system", "content": "Summarize supplied facts accurately and concisely."},
        {"role": "user", "content": "The deployment moved to Thursday. Priya owns the release. Summarize."},
    ],
    max_tokens=4096,
    temperature=0,
)
print(response.choices[0].message.content)

Stream the final answer

The OpenAI-compatible route streams server-sent events. LFM reasons before answering, so final-answer text may begin after a delay. Reasoning is returned separately as reasoning_content; display only delta.content when you want the final answer.

stream = client.chat.completions.create(
    model="local-general",
    messages=[{"role": "user", "content": "Explain the supplied plan in three bullets: ..."}],
    max_tokens=4096,
    stream=True,
    stream_options={"include_usage": True},
)
for chunk in stream:
    if chunk.choices:
        text = chunk.choices[0].delta.content
        if text:
            print(text, end="", flush=True)

Check the final finish_reason. A value of length means the token allowance was exhausted, possibly during reasoning. Increase max_tokens within the context limit if the task needs more room.

Request structured JSON

Use response_format and still validate the result against your application schema. A schema constrains the format; it does not establish that the facts are correct.

import json

response = client.chat.completions.create(
    model="local-general",
    messages=[{"role": "user", "content": "Extract owner and day: Priya will deploy on Thursday."}],
    max_tokens=4096,
    response_format={
        "type": "json_schema",
        "json_schema": {
            "name": "release",
            "strict": True,
            "schema": {
                "type": "object",
                "properties": {
                    "owner": {"type": "string"},
                    "day": {"type": "string"},
                },
                "required": ["owner", "day"],
                "additionalProperties": False,
            },
        },
    },
)
if response.choices[0].finish_reason != "stop":
    raise RuntimeError("The model did not finish; inspect the response before parsing.")
result = json.loads(response.choices[0].message.content)
print(result)

Application-controlled tools

Send function definitions in tools. The model returns structured tool_calls; your application validates arguments, executes the allowed function, and sends a tool message back. This service does not execute tools.

import json

messages = [{"role": "user", "content": "Look up the status of ticket INC-42."}]
tools = [{
    "type": "function",
    "function": {
        "name": "lookup_ticket",
        "description": "Look up a ticket by its ID.",
        "parameters": {
            "type": "object",
            "properties": {"ticket_id": {"type": "string"}},
            "required": ["ticket_id"],
            "additionalProperties": False,
        },
    },
}]

first = client.chat.completions.create(
    model="local-general", messages=messages, tools=tools, max_tokens=4096,
)
message = first.choices[0].message
messages.append(message.model_dump(exclude_none=True))
for call in message.tool_calls or []:
    arguments = json.loads(call.function.arguments)
    # Replace this illustrative result with a validated call to your ticket service.
    result = {"ticket_id": arguments["ticket_id"], "status": "resolved"}
    messages.append({
        "role": "tool", "tool_call_id": call.id,
        "content": json.dumps(result),
    })

if message.tool_calls:
    final = client.chat.completions.create(
        model="local-general", messages=messages, tools=tools, max_tokens=4096,
    )
    print(final.choices[0].message.content)
else:
    print(message.content)

Keep tool access rules in the calling application. Use supplied documents, retrieval, or tools when an answer needs current or organization-specific facts.

Ollama-style clients

Set the host to the service root, without /v1. Both /api/chat and /api/generate support normal JSON responses and newline-delimited JSON streams. The model stays loaded; keep_alive does not manage its lifecycle.

# pip install ollama
import os
import ollama

client = ollama.Client(
    host="https://device.example.invalid:8446",
    headers={"Authorization": f"Bearer {os.environ['LOCAL_GENERAL_API_KEY']}"},
    timeout=900.0,
)
response = client.chat(
    model="local-general",
    messages=[{"role": "user", "content": "Summarize these notes: ..."}],
    options={"num_predict": 4096, "temperature": 0},
    think=False,
    stream=False,
)
print(response.message.content)

think=False controls whether reasoning is shown in the response. LFM still performs reasoning internally, and those tokens still use its output allowance. A completed response reports done: true; done_reason: "length" indicates truncation.

Supported generation options include num_predict, temperature, top_p, top_k, min_p, repeat_penalty, and seed. Use format: "json" or a JSON schema for structured responses. Unsupported material options return an error instead of silently changing behavior.

Move a service from OSS 20B

  1. Point the service at the base URL appropriate for its client above and supply the API key.
  2. Set the requested model to local-general. For migration, this endpoint also accepts gpt-oss-20b:64k as an alias for LFM. That alias does not select OSS.
  3. Keep normal system/user/assistant messages. Remove manually embedded model tokens, GPT-specific stop strings, and assumptions about a particular tokenizer.
  4. Test a representative request and any JSON, streaming, or tool behavior your service uses. Recount token budgets with the new model.
  5. Check timeouts and retry policy. Budget for a queued request and model reasoning, and handle 429 with backoff.

Compatibility values reasoning_effort: "low", "medium", and "high" are accepted and ignored by this gateway. They do not select a reasoning mode. The policy is also identified in response headers. Use max_tokens to bound total generation.

Conversation history remains the caller's responsibility. Send the message history on each request; server-side conversation IDs and saved GPT token-state objects are not supported.

Service limits and behavior

ItemProvisioned setting
ModelLFM 2.5 24B A2B, QAD-Q4_0; text input and output
Context73,728 tokens shared by the formatted input, history, reasoning, and answer
Default / maximum output8,192 / 65,536 tokens, subject to remaining context
ConcurrencyOne active generation, up to 16 waiting requests
Maximum queue wait120 seconds
Request body limit8 MiB; byte size is a transport limit, not a token count
Default temperature0, matching the tested local baseline
Timeout guidanceStart with 900 seconds for ordinary requests. Larger output allowances can require substantially longer.
Supported APIsChat Completions, model listing, Ollama-style chat/generate and metadata
Other APIsResponses, embeddings, vision, model downloads, and model management are outside this service

The completed local public test measured about 13.6 generated tokens/second, with 31/32 HumanEval+ enhanced passes and 31/32 IFEval strict prompt passes. This is a small, single-request benchmark; application latency depends on prompt length, reasoning, output length, and queueing. It is not a concurrency or long-context quality guarantee.

Application request bodies and model output are not written to service logs. Operational logs contain lifecycle events and request metadata. Access to the service follows Tailscale network policy and the API key.

Model source: this service uses the QAD-Q4_0 file published in Liquid AI's own model repository. Its pinned revision and file SHA-256 are verified, and the backend checks the full file hash each time it starts. This establishes which release is running; it does not certify that any model is free of behavioral backdoors.

Troubleshooting

SymptomWhat to check
Cannot resolve or connect to the HTTPS hostVerify Tailscale is connected and this device can reach UCS on port 8446. Keep TLS certificate verification enabled.
401Supply the service API key in the Bearer header. An OpenAI cloud key is not this service's key.
400Read the error details: check model name, supported fields, options, token allowance, and message structure.
404Check the route and whether the client incorrectly added or omitted /v1.
429The queue is full or its wait budget was exceeded. Honor Retry-After when present and retry with backoff.
502, 503, or 504The backend may be loading, unavailable, or timed out. Check readiness and share the request ID with the service owner.
Empty final answer or truncated JSONInspect finish_reason / done_reason. Reasoning can exhaust the output allowance before the final answer.
Streaming response seems silentThe model may still be reasoning. Ensure your proxy allows streaming and your application distinguishes reasoning from answer text.

Liveness checks the gateway process. Readiness checks whether the model backend is available. Neither endpoint needs an API key; generation and model metadata do.
